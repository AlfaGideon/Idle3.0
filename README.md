# Idle Arc Helper

Неофициальный Android-помощник для IdleArc. Просматривает конфигурацию игры и данные аккаунта и показывает выбранные значения в перемещаемом окне поверх приложений. Действия в игре не автоматизируются: клиент выполняет только GET-запросы.

## Установка и сборка

Нужны Android Studio, JDK 17, Android SDK 35 и доступ в интернет для Gradle и зависимостей. Откройте проект в Android Studio и соберите **Build → Build APK(s)** либо выполните `./gradlew assembleDebug`. APK появится в `app/build/outputs/apk/debug/app-debug.apk`. Debug-сборка подписана отладочным ключом и не предназначена для публикации. Также есть workflow `.github/workflows/android.yml`: после запуска в GitHub Actions скачайте артефакт `IdleArcHelper-debug`.

Минимальная версия — Android 8.0 (API 26). Для плавающего окна приложение запросит разрешение «Поверх других приложений». На Android 13+ желательно разрешить уведомления: постоянное уведомление позволяет открыть приложение или остановить окно. Окно можно закрыть крестиком, в уведомлении или в приложении; оно не запускается само после перезагрузки.

## Использование

1. Нажмите «Войти в IdleArc», введите email и пароль в форме приложения и нажмите «Войти и проверить данные». Данные отправляются по HTTPS на официальный `/api/login`; пароль и email не сохраняются. При истечении токена нужно войти снова.
2. Откройте «Данные персонажа», войдите в нужные вложенные разделы и нажмите на значение. В окне подробностей можно закрепить его (до 8). Звёздочка означает, что поле закреплено; повторное нажатие удаляет его.
3. Нажмите «Запустить плавающее окно», предоставьте системное разрешение и при необходимости нажмите кнопку запуска ещё раз. Перетаскивайте окно за заголовок. Обновление — каждые 30 секунд или по кнопке ↻.
4. «Конфигурация игры» позволяет просматривать открытые данные API. Для известных полей показывается русское название, для других — автоматический или частичный перевод составных ключей. Исходный ключ и значение доступны при нажатии на поле. Значения не преобразуются с предположением о единицах измерения. При истечении сессии войдите заново.

Изменение значений на сервере пока не поддерживается: данные dashboard и config получены GET-запросами, а проверенный API записи для произвольных полей не предоставлен. Просмотр не меняет игру. Для настоящего редактора необходимы документация серверных методов, форматы запросов и соответствующие права доступа.

## Логи авторизации

Откройте «Логи и диагностика» на главной, очистите старые события, повторите вход и проверку данных, затем вернитесь в логи и нажмите «Скопировать логи». Экран доступен также прямо из окна входа и с экрана ошибки. События содержат этап входа и запросов, HTTP-код, категорию редиректа, тип ответа, факт наличия токена и тип сетевой ошибки. Последние 200 событий хранятся только в памяти процесса и не отправляются автоматически. Email, пароли, токены, cookie, параметры URL и тела ответов не записываются. Перед отправкой проверьте содержимое буфера; скриншоты страницы входа не должны содержать личные данные. Если сайт показал ошибку внутри формы, перепишите её текст отдельно, не указывая логин и пароль.

## Поиск потокового соединения с телефона

Откройте «Сканирование онлайн-потока». Встроенная веб-версия требует отдельного входа в аккаунт сайта; API-токен в неё не передаётся. Выполните несколько действий в игре, нажмите «Результаты» и скопируйте отчёт. Сканер регистрирует JavaScript WebSocket, EventSource, и ответы fetch/XHR с типом `text/event-stream` в контексте страниц idlearc.com. В отчёте только типы и этапы соединений, безопасные части пути, тип сообщения/разрешённые имена полей, некоторые стандартные события Pusher и обобщённая категория канала; данные сообщений, заголовки, пароли, токены и query-параметры не записываются. Неизвестные внешние домены и неизвестные сегменты пути скрываются; домены стандартных кластеров Pusher могут отображаться. Имена каналов и содержимое сообщений не сохраняются. Журнал хранится в памяти до закрытия экрана.

Ограничения: нужен современный Android System WebView с поддержкой document-start script и WebMessageListener; доступ к сторонним сайтам из этого окна заблокирован. Сканер не видит трафик других приложений, Service Worker / Web Worker, и не гарантирует обнаружение всех потоков или формата сообщений. Отсутствие события не доказывает отсутствие потока. Он ничего не отправляет автоматически; перед пересылкой отчёта проверьте его содержимое.

## Обновление данных

Пока используется обычный GET: на экране данные загружаются при открытии или обновлении, а плавающее окно повторяет запрос каждые 30 секунд. Это не поток в реальном времени. Возможность WebSocket или SSE в доступных API и во втором проекте не подтверждена. Для подключения настоящего потока нужен его адрес, формат сообщений и способ авторизации; клиент не может создать поток, если сервер его не предоставляет.

## API и ограничения

* `GET https://idlearc.com/api/config/game` — открытая JSON-конфигурация; на момент исследования содержала `version`, `itemization` и другие разделы.
* `POST https://idlearc.com/api/login` — форма отправляет JSON с `email`, `password` и `device_name` и получает `token`. Такой механизм используется в проекте [IdleArc2.0](https://github.com/AlfaGideon/IdleArc2.0). `GET https://idlearc.com/api/dashboard` использует `Authorization: Bearer <token>`. Ответ авторизованного аккаунта и структура его полей не были доступны при разработке. Поэтому вместо предположений о схеме реализован универсальный просмотр JSON; доступные значения зависят от сервера. Вложенные поля массива закрепляются по индексу и при изменении порядка могут указывать на другой элемент.
* Email и пароль отправляются только на фиксированный HTTPS-адрес IdleArc, без перехода по редиректам. Они не сохраняются; пароль может временно находиться в памяти во время запроса. Токен шифруется AES-GCM ключом Android Keystore, резервное копирование данных приложения выключено. При выходе локальный токен, старые cookies и выбор полей удаляются; отзыв токена на сервере не выполняется. Ответы API и значения полей не сохраняются на диск. Никакой сторонней аналитики нет.
* Это не официальный клиент. Изменения авторизации, защиты сайта, API или ограничений производителя Android могут потребовать обновления. Работа входа, авторизованного dashboard и окна на конкретном устройстве требует проверки с реальным аккаунтом.
