# Idle Arc Helper

Неофициальный Android-помощник для IdleArc. Просматривает конфигурацию игры и данные аккаунта и показывает выбранные значения в перемещаемом окне поверх приложений. Действия в игре не автоматизируются: клиент выполняет только GET-запросы.

## Установка и сборка

Нужны Android Studio, JDK 17, Android SDK 35 и доступ в интернет для Gradle и зависимостей. Откройте проект в Android Studio и соберите **Build → Build APK(s)** либо выполните `./gradlew assembleDebug`. APK появится в `app/build/outputs/apk/debug/app-debug.apk`. Debug-сборка подписана отладочным ключом и не предназначена для публикации. Также есть workflow `.github/workflows/android.yml`: после запуска в GitHub Actions скачайте артефакт `IdleArcHelper-debug`.

Минимальная версия — Android 8.0 (API 26). Для плавающего окна приложение запросит разрешение «Поверх других приложений». На Android 13+ желательно разрешить уведомления: постоянное уведомление позволяет открыть приложение или остановить окно. Окно можно закрыть крестиком, в уведомлении или в приложении; оно не запускается само после перезагрузки.

## Использование

1. Нажмите «Войти в IdleArc» и войдите на официальном сайте в открывшемся окне. Нажмите «Готово · проверить данные».
2. Откройте «Данные персонажа», войдите в нужные вложенные разделы и нажмите на значения для закрепления (до 8). Звёздочка означает, что поле закреплено; повторное нажатие удаляет его.
3. Нажмите «Запустить плавающее окно», предоставьте системное разрешение и при необходимости нажмите кнопку запуска ещё раз. Перетаскивайте окно за заголовок. Обновление — каждые 30 секунд или по кнопке ↻.
4. «Конфигурация игры» позволяет просматривать открытые данные API. При истечении сессии войдите заново.

## Логи авторизации

Откройте «Логи и диагностика» на главной, очистите старые события, повторите вход и проверку данных, затем вернитесь в логи и нажмите «Скопировать логи». Экран доступен также прямо из окна входа и с экрана ошибки. События содержат этап загрузки, HTTP-код, категорию редиректа, тип ответа, факт наличия cookie и тип сетевой ошибки. Последние 200 событий хранятся только в памяти процесса и не отправляются автоматически. Пароли, значения cookie, параметры URL и тела ответов не записываются. Перед отправкой проверьте содержимое буфера; скриншоты страницы входа не должны содержать личные данные. Если сайт показал ошибку внутри формы, перепишите её текст отдельно, не указывая логин и пароль.

## API и ограничения

* `GET https://idlearc.com/api/config/game` — открытая JSON-конфигурация; на момент исследования содержала `version`, `itemization` и другие разделы.
* `GET https://idlearc.com/api/dashboard` — без входа перенаправляет на `/login`. Ответ авторизованного аккаунта и структура его полей не были доступны при разработке. Поэтому вместо предположений о схеме реализован универсальный просмотр JSON; доступные значения зависят от сервера. Вложенные поля массива закрепляются по индексу и при изменении порядка могут указывать на другой элемент.
* Вход проходит в WebView на HTTPS-сайте IdleArc; приложение не запрашивает и не хранит пароль отдельно. Cookie WebView используются для GET-запросов только на `idlearc.com`; приложение не отправляет их третьим сторонам. При выходе локальные cookies и выбор полей удаляются. Ответы API и значения полей не сохраняются на диск приложением, но WebView может хранить данные сайта. Никакой сторонней аналитики нет.
* Это не официальный клиент. Изменения авторизации, защиты сайта, API или ограничений производителя Android могут потребовать обновления. Работа входа, авторизованного dashboard и окна на конкретном устройстве требует проверки с реальным аккаунтом.
